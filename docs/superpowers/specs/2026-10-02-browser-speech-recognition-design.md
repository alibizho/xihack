# 浏览器语音识别设计

## 目标

在易忆现有语音记事流程中，使用浏览器自带的中文语音识别，把用户说的话转换成真实文本并填入事务输入框，适配移动端。

## 方案

替换目前 `MediaRecorder` 录音后返回固定演示文本的流程，改用浏览器 `SpeechRecognition`（兼容前缀 `webkitSpeechRecognition`）。用户点“开始录音”后启动 `zh-CN` 连续识别；识别中的临时结果可显示在输入框中，用户点“结束录音”或识别自然结束后保留最终结果。现有编辑、整理预览和保存流程保持不变。

语音入口和识别状态仍放在 `src/features/tasks/TaskComposer.tsx`，相关按钮及状态样式放在同目录 CSS。识别服务只依赖浏览器 API，不上传音频到项目后端。桌面与移动布局沿用当前全宽触控按钮和输入框。

## 失败处理

- 浏览器没有语音识别 API 时，说明当前浏览器不支持语音识别，并保留手动输入。
- 麦克风权限被拒绝、设备不可用或识别报错时，显示简体中文提示，用户可继续手动输入或重试。
- 识别返回空内容时不覆盖已有输入。
- 组件关闭或页面切到后台时停止识别，避免麦克风继续工作。

## 验收

- 在支持 Web Speech API 的浏览器中说普通话，停止后输入框显示识别出的文本，而非固定示例。
- 用户可以修正识别结果，再使用现有“整理并预览”流程。
- 不支持 API 或权限失败时，显示可理解的提示且文字输入仍可用。
- 开始/结束按钮状态和提示在移动视口下可操作、可读。
- `npm run build` 与 `npm test` 通过。
