# 2026-10-02 线上全链路验收

环境：`https://jianwenjiuzhou.cloud`，前端集成分支 `09b08da`，后端子模块 `1c0e28d`。正式站点使用临时账号测试，完成后删除账号及其级联数据；后端测试使用独立的 PostgreSQL 17 临时数据库，完成后移除。

| 链路 | 结果 | 证据与边界 |
| --- | --- | --- |
| 页面与静态资源 | 通过 | 首页和打包 JS 返回 200；浏览器可进入今天、事务、训练、助手、我的页面。 |
| 账号与隔离 | 通过 | 注册、注销、密码登录、会话 Cookie、CSRF 拦截均按预期；另一账号读取任务和提案均返回 404。 |
| 任务 | 通过 | 创建、修改、完成、删除都经待确认提案；未确认不写入，重复确认使用相同幂等键只产生一个任务。 |
| 语音文字校准 | 通过 | `/api/transcriptions` 把“明天下午三点提醒我整理联调任务”识别为创建意图和分钟级时间。此接口是文本规则校准，没有调用 MiMo。 |
| 浏览器麦克风与服务端音频回退 | 未验证 | 没有真实设备录音；当前部署未配置本地 Whisper 模型。浏览器语音识别产生文字后才使用上述校准接口。 |
| 专注训练 | 通过，存在一次重试 | 浏览器完成一局 5×5 训练。首次复盘请求显示 `Failed to fetch`，重试后返回 MiMo 分析；切换页面再回来，训练记录可展开查看复盘。独立 HTTPS API 请求也返回 `observation` 和 `suggestion`。 |
| 事务 Agent 问候与 SSE | 通过 | 问候 run `completed`，SSE 返回事件。MiMo 服务端请求链路可达。 |
| 事务 Agent 查询与提案 | **失败** | 查询任务有时 `INVALID_TOOL_CALL`，有时把 `<tool_call>` 原文作为已完成回答；提案请求 `INVALID_TOOL_CALL`，没有产生 `source=agent` 提案。见 [后端交接记录](backend-agent-handoff.md)。 |

代码验证：前端 `npm run build` 成功，`npm test` 为 6/6；后端执行迁移后，在独立测试库运行 `pytest -q -p no:cacheprovider` 为 41/41。后端单元与集成测试使用模拟模型响应，无法证明真实 MiMo 工具流兼容。验收后正式站点和 `/healthz` 均返回 200，正式数据库与前后端服务仍在运行。

架构核对：同学 2 后端是**一个事务 Agent**，注册了 `search_tasks`、`get_task` 和四个任务提案 Tool；前端助手页确实提交其 run。专注训练复盘是 Node 服务的独立 MiMo 提示词请求，不经过该事务 Agent。浏览器语音识别及文本校准也不经过该事务 Agent。
