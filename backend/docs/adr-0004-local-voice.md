# ADR 0004：前端本地转写，后端校准与业务核验

日期：2026-10-02

## 决定

1. 前端负责麦克风权限、录音和本地语音转文字，展示可编辑的初步文字。默认只向后端提交文字，不上传原始音频。
2. 后端将初步文字视为不可信输入：校准文本格式、按用户时区标准化日期/时间、检查内容完整性、识别任务意图，并校验字段、目标任务归属和业务规则。无法可靠判断时返回澄清，不猜测或写任务。
3. 草稿校准不创建对话消息或 Agent Run。只有用户主动发送校准或自行编辑后的文字，才进入现有消息/run 流程。所有任务创建、编辑、完成、删除仍须形成待确认提案；用户明确确认后，统一确认用例才写入任务。
4. 只有前端本地转写低置信度、用户主动重试或后端无法判断时，才可提供可选的音频上传/二次转写；进入该流程前向用户说明并取得主动操作。音频不能作为默认请求的一部分。
5. 阶段 6 的前端本地模型、浏览器兼容性、音频回退格式、低置信度阈值，以及隐私告知和临时音频保留/清理策略见 [ADR 0005](./adr-0005-speech-stage-6.md)。可选回退若无法满足这些条件，保留文字输入与人工修改路径。

本决定取代 [ADR 0001](./adr-0001-stage-0-decisions.md) 中“录音结束后上传、后端默认转写”的语音路径；既有任务提案确认规则不变。后端接口的阶段 6 实现见 ADR 0005 和当前 OpenAPI。
