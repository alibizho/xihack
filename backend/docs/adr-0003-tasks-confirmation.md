# ADR 0003：阶段 2 任务与统一确认

日期：2026-10-02。用户确认阶段 2 的最小字段、日期精度、统一确认与删除规则。

## 任务与日期

- 任务标题必填；说明、分类、截止时间可选；重要与紧急为独立布尔值。状态为 `open` 或 `completed`，每次确认写入增加版本。
- 截止时间是带时区的结构化值：仅日期使用 `date` 与 IANA `timezone`；精确到分钟使用带 UTC 偏移的 `at` 与 IANA `timezone`，并校验两者一致。服务端保存日期原值或绝对时刻及原时区，不把仅日期解释成午夜截止。
- 当前没有已确认且必须跨任务保存的偏好字段，因此阶段 2 不新增偏好表；后续如需明确用户时区，再按用户决定新增。

## 统一确认

- 手动创建、编辑、完成、删除统一通过 `POST /api/proposals` 保存预览；Agent 在阶段 5 复用相同应用用例，当前不开放 Agent 来源字段给客户端。
- 提案创建使用 `client_request_id` 保证重试幂等；确认使用 `idempotency_key`。待确认提案 15 分钟有效，确认时在同一事务中复查账号、状态、目标版本、有效期和幂等键。取消不修改任务。
- 创建提案时不写任务。更新与完成必须携带目标任务当前版本；删除确认后任务从当前数据库永久移除，并使该任务的其他待确认提案失效。确认响应保存当时的回执，重复确认以同一幂等键返回同一回执。
- 备份保留期限在部署阶段决定；本阶段只保证当前数据库与任务 API 无恢复入口。未来对话历史中的文字如何保留，在对话阶段确定。

## HTTP 边界

任务路径只读：`GET /api/tasks` 和 `GET /api/tasks/{task_id}`。所有写入走提案确认入口；不暴露可绕过确认的任务 POST/PATCH/DELETE。
