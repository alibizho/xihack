# 拾序后端规则

本目录是当前仓库的后端服务；Git 根目录在上一级。另读[项目级规则](../AGENTS.md)。阶段顺序、交付物及验收以[开发计划](docs/development-plan.md)为准。

## 阶段与团队协议

- 实施前确认用户已批准总计划及当前阶段；一次只做一个阶段。完成后交付结果并停下，等待下一阶段确认。
- 每阶段只有一名主实施者修改目标代码和测试。其他协作者做调研、只读审查或运行测试；需要写文件时先分配不重叠的文件并向主实施者交接。`review-agent` 始终只读，只报告有证据的问题，不修改代码。
- 范围外问题记入交接，不顺带实现。交接须列明已完成内容、未决问题、风险、验证命令与结果、下一步；每项验收标准标明通过、失败或未验证。
- Git 操作在当前仓库根目录执行。提交仅含当前阶段文件，使用 Conventional Commit；推送前核对仓库根目录与 GitHub remote。

## 后端实施步骤

1. **冻结本阶段接口**：从开发计划取目标阶段，再读取对应设计，列出本阶段要实现的 API、数据状态和未决参数。**完成标准**：每个要改的接口/模型都有可查的契约或已确认决定；冲突和待定项已登记，阻塞项在编码前交由用户决定。
2. **保持分层与归属**：依赖方向为 Presentation / Agent / Worker → Application → Domain；Infrastructure 实现 Application ports，组合集中在入口。API schema、应用 DTO、领域对象与 ORM 模型各司其职。认证账号只从服务端会话进入用例；所有业务读写按账号限定，Agent Tool 只调用 Application 用例。**完成标准**：本阶段新增的路由、Tool 与 Worker 不绕过用例直接改业务表；涉及账号数据的路径有跨账号拒绝验证。
3. **守住事务与确认**：每个请求或 worker job 使用独立数据库 Session；用例定义提交/回滚边界。所有任务创建、编辑、完成和永久删除先保存待确认意图，只有确认用例能真正写任务；确认时复查归属、版本、状态、有效期及幂等键。**完成标准**：本阶段涉及的任务写入对未确认、重复确认、版本冲突和失败回滚均有明确结果，不会部分或重复写入；尚未实现的路径留给对应阶段验收。
4. **同步契约与持久化**：API 变更同步 OpenAPI/示例及错误语义；表结构变更提供 Alembic 迁移。Run/事件以 PostgreSQL 为持久真相，SSE 负责呈现与重连；worker 领取、重试和恢复不得依赖进程内状态。**完成标准**：本阶段更改的契约与实际响应一致；新增迁移在可丢弃数据库可升级并按迁移策略验证回退；若本阶段涉及 run，则验证断线或重试不会丢失已接受的 run 或重复业务副作用。
5. **做针对性验证**：每阶段只添加少量能检验真实风险的测试：纯规则用单元测试，认证/错误/契约用接口测试，账号隔离、事务、迁移、worker 恢复用数据库集成测试。遵循现有 `pyproject.toml`/工具配置；对本阶段修改的 Python 文件运行 `uv run ruff format <阶段文件>`，收尾运行 `uv run ruff check .` 与 `uv run ruff format --check .`；格式化后重跑受影响的测试。全仓格式检查若命中范围外文件，报告而不顺带修改。**完成标准**：本阶段每条验收标准有对应测试或可复现人工检查，格式与静态检查通过，报告实际命令、结果与未覆盖风险；不为实现细节或文件数量凑测试。

## 补丁落盘检查

- 含模板占位符、反斜杠或大量新文件的补丁按功能拆成小块；每块应用后检查工具结果与目标文件。失败时先核对文件状态，再修正补丁重试，不能假定“全部未落盘”或继续基于未确认的文件修改。
- 对迁移模板等易受补丁语法影响的文件，单独应用并先做语法/生成检查；进入下一块前确认预期文件内容已落盘。**完成标准**：补丁结果、目标文件清单和后续验证对象一致。

## 持续约束

- Python 代码使用类型标注、明确的依赖和小而清楚的用例；遵循仓库格式化、静态检查与测试配置。新依赖须服务当前阶段的功能或验证需要。
- 认证采用服务端可撤销 Cookie 会话；敏感操作校验授权与 CSRF/来源。统一映射可恢复/不可恢复错误，响应带可追踪请求 ID；日志保留必要元数据，排除密码、Cookie、密钥、任务/对话正文及原始音频。
- 单 Agent/单 LLM 的首期范围见开发计划。模型输出仅是输入数据，结构化 schema 不能代替授权；不建立跨对话长期记忆。任务与对话删除各自独立；语音草稿未经用户发送不创建对话消息。
- `D:/proj/laoshiren` 仅供调研其边界和验收做法。引入组件前先证明当前阶段需要；范围外发现留在交接记录。
